# Edge-case review: bookvie UX spines

**Verdict.** The spines handle the happy path and the single-state cases well: empty library, 0 or many Waiting rows, no Measured pace, validation, duplicates, and reduced motion. They break down where states overlap. A Book can be finished and re-read, Up next and paused, a Side read and Main, and the spines give each surface a single status with no precedence rule. They also never say how a library full of already-read books gets finish dates. A developer would have to guess the data rules behind the shelf, Stats, and Measured pace, so the pair needs one more pass before epics.

Severity reflects downstream impact: **critical** means the data model or a core metric is guessed; **high** means a core screen or flow behaves differently depending on who builds it; **medium** means a visible inconsistency or a small guess; **low** means polish.

## Readings, finishing, re-reads

- **[critical]** The spines never say how already-read Books get finished Readings with past dates. Flow 1 ends with "24 of 73 finished", yet the only finish paths are "enter the last page" and "Mark finished", and both stamp today. Back-filling the paper diary would put every historical Book into this month's Stats. It would also give Measured pace a start date equal to its finish date, so 0 days, or invent a start date. Pace, the "~N days left" line, and the library calculator would all be wrong from day one (EXPERIENCE.md § Component Patterns → Book detail, Finish dialog; PRD FR-14, FR-16, Glossary "Measured pace"). *Fix:* Add an "Add past reading" (or "Mark as read before") action on Book detail with optional start and finish dates. Say how undated past Readings count: excluded from Stats periods and from Measured pace, but included in the "X of Y finished" meter. Record this in prd-deltas.md.
- **[high]** Book states overlap with no precedence rule. A Book can be finished and re-read as Main, finished and Up next, Up next with a paused Reading, a Side read and Up next, or a Side read with a paused Reading. The spine accessible name allows one status. The popover lists one primary action per state, and "Up next → Start reading" is wrong when the Up next has a paused Reading (it should be Resume). DESIGN draws one marker per spine. The re-read spine is "[ASSUMPTION] keeps its full color", but the Main-book rule says "outlined in its color, filled to %"; these contradict for a re-read Main book (EXPERIENCE.md § Component Patterns → Spine, Spine popover; § Bookcase; DESIGN.md § Components → Spine). *Fix:* Add a state table to EXPERIENCE.md with orthogonal axes: read-ever (yes/no), Reading state (none, Main, paused), Up next (yes/no), Side read (yes/no). For each combination give the spine fill, the marker (one dot or two), the accessible-name status string (for example "finished, re-reading, 12%"), and the popover primary action.
- **[high]** "Mark finished" on a Reading that isn't Main is undefined. Book detail offers Mark finished in some states, and Done always goes to Home, plays the fill on the slice, and switches the Main book card to no-Main-book. That's wrong when the finished Reading was paused, Up next, or never started. Book detail doesn't say which states show Mark finished. Finishing an Up-next or Waiting Book doesn't say whether it leaves Up next or Waiting. Finishing an unread Book with no Reading doesn't say whether a Reading is created, or with which start date (EXPERIENCE.md § Component Patterns → Finish dialog, Book detail). *Fix:* List the states where Mark finished appears. For a Reading that isn't Main: stay on Book detail, play no fill (or play it only if the spine is visible), leave the Main book alone, and remove the Book from Up next and Waiting. State what an unread Book finish creates.
- **[high]** Editing the page count below the current page is undefined. If a Reading sits at p.300 and Pages is edited to 250, the spines don't say whether the gauge reads 120%, whether the page clamps, or whether the Finish dialog opens. Card notes on pp.260–270 fall out of range, and the spines don't say whether they are refused, flagged, or kept. Stats use "all of a Reading's pages", so finished Readings would change retroactively (EXPERIENCE.md § Component Patterns → New book panel edit mode, Page field, Card note panel; PRD FR-10, FR-17). *Fix:* On Save changes, validate Pages ≥ the highest current page of any active or paused Reading and ≥ the highest Card note page, with an inline message. Alternatively, clamp the page and say so. Decide whether finished Readings store their own page count for Stats.
- **[medium]** Cancelling the Finish dialog leaves a loop. The Reading sits at the last page, so the gauge reads 100%, the Main spine looks fully filled (like a finished Book), and "~0 days left" shows. Pressing Update again with the same value either reopens the dialog or does nothing; the spines say neither (EXPERIENCE.md § Component Patterns → Page field, Re-entry line). *Fix:* Re-submitting the last page reopens the Finish dialog. Hide "~N days left" when 0 pages are left. Keep the Main-book marker so the spine stays distinguishable from a finished one.
- **[medium]** The finish moment for a re-read has no defined effect. The spine is already full color under the re-read assumption, the meter count doesn't change, and the live region still says "25 of 54 finished". Popover: a finished Book has "no primary action" and no "Start reading" link, so a re-read can start only from Book detail; the spines don't say whether that's intended (EXPERIENCE.md § State Patterns → Finish moment; § Component Patterns → Spine popover). *Fix:* State that a re-read plays only the highlight ring (no fill), and that the line reads "Finished *X* again." or stays the same. Decide whether the popover offers "Read again" as a link.
- **[low]** For a 1-page Book, the gauge ticks "0 · half · total" read "0 · 0.5 · 1" (DESIGN.md § Components → Gauge). *Fix:* Round the half tick, or drop it when Pages < 4.

## Up next, Waiting for you, Side reads

- **[high]** It's unclear whether a paused Up next Book also appears in Waiting for you. EXPERIENCE says Waiting lists "every paused Reading". FR-7 says a displaced Up next "moves to Waiting for you", which implies it wasn't there while Up next. Flow 3 puts the paused *Left Hand* in Up next only. If Waiting does include it, the Book appears twice on Home with two markers (EXPERIENCE.md § Component Patterns → Section pane; PRD FR-7, Glossary). *Fix:* Define Waiting for you as paused Readings excluding the Up next Book, and use the same definition for the "(N)" count, the spine marker, and the Library pace scope.
- **[high]** Starting a Book when an Up next exists displaces that Up next silently. Flow 3 sends the previous Up next "back to the catalog", but the Start dialog's trade-off line names only the paused Main book. That breaks the PRD's "every switch a deliberate, visible trade-off" (EXPERIENCE.md § Component Patterns → Start dialog; Flow 3 step 6). *Fix:* Add a second trade-off line when an Up next exists and isn't the Book being started: "*Z* leaves Up next." (or "*Z* moves to Waiting for you.").
- **[medium]** Set as Up next exists only on unread Books in the popover. Paused Books get Resume, finished Books get nothing, and Book detail has no Set as Up next. So FR-7 ("set one Book as Up next", "It can be unread or paused") can't be done for a paused Book, and a planned re-read can't be queued (EXPERIENCE.md § Component Patterns → Spine popover, Book detail; PRD FR-7). *Fix:* Add Set as Up next to Book detail for any Book that isn't Main and isn't already Up next. Optionally add it as a link in the paused popover.
- **[medium]** Side-read promotion conflicts with other states. Promoting a Side read that already has a paused Reading would show both Resume (keep the page) and the required "Which page?" field. Starting a Side read from the Catalog popover or Book detail (not from On the side) doesn't say whether "Which page?" appears. After promotion, nothing says whether the Side read marker clears and frees a slot. A Side read that gets finished doesn't say whether it stays in On the side. "Which page?" = the last page doesn't say whether it finishes at once (EXPERIENCE.md § Component Patterns → Start dialog, Section pane; PRD FR-8). *Fix:* "Which page?" appears whenever a Side-read Book is started by any route, prefilled with the paused page if one exists. Promotion and finishing both clear the Side read marker. The last page goes straight to the Finish dialog.
- **[medium]** Deleting a Book in a special state is underspecified. The Confirm copy doesn't mention that the Book is the Main book, Up next, or waiting. Deleting Up next doesn't say whether Up next stays empty or gets a suggestion from Waiting. Deleting from Book detail doesn't say where the user lands. A pending "Finished *X*." header line for a deleted Book has no rule (EXPERIENCE.md § Component Patterns → Confirm dialog). *Fix:* Add the state to the Confirm copy ("Delete *X*? It is your Main book. Its readings and card notes are deleted too."). After deletion, go to Catalog and leave the vacated role empty (no auto-promotion, consistent with "nothing starts automatically").
- **[medium]** Waiting for you with 20+ rows pushes the bookcase slice far below the fold, because the grid has no cap and the slice sits underneath. The finish moment then plays off-screen and is lost forever ("never replays") (EXPERIENCE.md § State Patterns → Waiting for you: many, Finish moment; DESIGN.md § Layout → Home). *Fix:* Scroll the finished spine into view before playing the fill, or play it only once the spine is in the viewport. Optionally cap visible Waiting rows with "Show all (N)" without dropping the count.
- **[low]** Pause has no confirmation and no defined effect on an existing Up next. Pausing makes the Main book Up next, which displaces the current one, with no trade-off shown (EXPERIENCE.md § Component Patterns → Book detail). *Fix:* Show the same displacement line in a small confirm, or state that Pause moves the old Up next to Waiting or the catalog silently.

## Home slice and bookcase scale

- **[high]** The slice rule doesn't include the Main book's row. The rule is "row with Up next, then rows with recent finishes", but Flow 2 and the Page field rule say the Main book spine fill updates on the slice. With 500 Books, the Main book is usually on another row (EXPERIENCE.md § Bookcase → Home slice vs § Component Patterns → Page field, Flow 2 step 4). *Fix:* Change the slice priority to the Main book row first, then the Up next row, then the most recent finishes, up to 3 rows.
- **[medium]** Rows depend on viewport width, so the slice changes as the window is resized. "Catalog sort order" for the slice isn't tied to a stored sort: the spines don't say whether it is the last sort chosen on Catalog or always the default (EXPERIENCE.md § Bookcase → Ordering, Home slice; Open Question 7). *Fix:* The slice and the Catalog share one remembered sort. The slice recomputes on resize. State this.
- **[medium]** The rules for long and non-Latin titles are incomplete. Two-line spine labels don't say how overflow ends (ellipsis or hard clip). `writing-mode: vertical-rl` sets CJK upright by default, which contradicts "spines rotate any script identically". No truncation rule exists for the 34px Main-book title, popover subtitles, or Waiting rows in a 320px column. A spine's accessible name with 8 authors isn't specified (DESIGN.md § Layout → Spine sizing, § Typography; EXPERIENCE.md § Component Patterns → Spine). *Fix:* Specify `text-orientation: sideways` (or accept upright CJK explicitly) and use an ellipsis on line 2. Clamp the Main title to 3 lines and pane titles to 2 lines, with the full text in a `title` attribute or the accessible name. Name the spine with the first author plus "and N others".
- **[medium]** "Sort by author" is undefined for multiple authors and name order. Authors are typed as "Ursula K. Le Guin" in one semicolon-separated field, so it's unclear whether the sort uses the first author's first or last word, how it handles diacritics and non-Latin scripts, and what the tie-breaker is (EXPERIENCE.md § Bookcase → Ordering; Agent Label Contract → Author(s)). *Fix:* Sort by the first listed author string with locale-aware `Intl.Collator`, then by title. State that last-name sort is out of scope, or add a "Sort as" field.
- **[low]** With ~500 Books, lazily rendered rows mean browser find (Cmd+F) can't reach off-screen spines. The List view has no paging and no clickable column sort. The popover's "anchored above" placement has no flip rule for top-row or edge spines (EXPERIENCE.md § Bookcase → Catalog scale; DESIGN.md § Components → Spine popover). *Fix:* Accept it, or render all rows as lightweight DOM (500 buttons is cheap). Add a flip/shift rule for the popover.

## Measured pace, "days left", relative times

- **[high]** Measured pace can divide by zero or produce extreme values. A Reading started and finished the same day gives 0 days. Pace below 1 page/day gives "~1,240 days left". The calculator prefill doesn't say whether it is rounded or shown as 0.37. "About N months" has no rule for under 1 month or over several years. The Library scope with 0 pages left has no result rule (EXPERIENCE.md § Component Patterns → Re-entry line, Pace calculator; PRD Glossary "Measured pace", FR-15). *Fix:* Count days inclusively (minimum 1). Prefill with one decimal. Format results as days under 60, months under 24, otherwise years. For 0 pages left show "Nothing left to read." or hide the result. Cap or round "~N days left" to weeks or months beyond 60 days.
- **[medium]** "Last updated" baseline and clock rules are missing. It isn't stated whether resuming a paused Reading or a Side-read promotion resets the timestamp; if not, a book resumed after 60 days greets the user with "Last updated 60 days ago", which reads as reproach. Calendar days vs 24-hour periods isn't specified. A timestamp in the future (clock moved back, timezone change) would give "-1 days ago". Multi-year spans have no format (EXPERIENCE.md § Component Patterns → Re-entry line; prd-deltas #18). *Fix:* Start and resume set the timestamp. Compute local calendar days and clamp negatives to "today". Show "over a year ago" beyond 365 days. Apply the same rules to "Last export".
- **[low]** The Home header date and every relative time go stale when the tab stays open past midnight (EXPERIENCE.md § State Patterns; DESIGN.md § Layout → Home). *Fix:* Recompute on window focus or visibility change.

## Spine color

- **[medium]** "From cover" vs automatic is ambiguous. The Spine color field is "`#RRGGBB` or empty (empty = automatic)". Choosing the "From cover" chip could store the hex (frozen) or clear the field (follows cover changes). If a cover is replaced later, it isn't clear whether an automatic color re-derives, and a user can't tell a frozen color from an automatic one. The popover has no "Automatic" option for cover-less Books once a swatch is picked. An invalid hex typed by the agent has no validation message (EXPERIENCE.md § Component Patterns → Spine popover; Agent Label Contract → Spine color; DESIGN.md § Spine colors). *Fix:* "From cover" means empty (automatic, re-derived when the cover changes); add an "Automatic" choice when there's no cover. Make invalid hex a validation error with the message "Spine color must be #RRGGBB or empty."
- **[medium]** A cover-derived color can disappear against the shelf. The label rule guarantees text contrast on the spine, but nothing guarantees spine-vs-`shelf-wall` or plank contrast. A cream or birch-colored cover makes a read spine look like an unread one or vanish, in light theme especially; the same applies to a near-black spine on the dark wall (DESIGN.md § Spine colors, § Contrast). *Fix:* Require read-spine fill ≥ 3:1 against `shelf-wall` in both themes, nudging lightness as the label rule does, or add a 1px `spine-unread-outline`-weight edge to every read spine.
- **[low]** Curated-color assignment for cover-less Books is "stable per Book (e.g. from id)", but after a restore, ids could change and so would colors (DESIGN.md § Spine colors [ASSUMPTION]). *Fix:* Persist the resolved automatic color, or require ids to survive export and restore.

## Card notes

- **[medium]** The page-range parsing rules are incomplete. Reversed ranges (45–42), equal ranges (42–42), spaced ranges ("42 – 45", "42 - 45"), a "p." prefix, and multiple ranges aren't specified. Flow 6 says the range minimum is 1 but the Page field allows 0, and the Card note panel prefills the current page, so at p.0 it prefills an invalid "0". The panel from Book detail on an unread Book has no current page to prefill (EXPERIENCE.md § Component Patterns → Card note panel; Flow 6 failure path). *Fix:* Trim whitespace and accept "p."/"pp." prefixes. Swap reversed ranges silently (or refuse them with a message) and store 42–42 as 42. The valid range is 1..Pages. Prefill with max(current page, 1), or leave it empty when there's no Reading.
- **[medium]** Pile edge cases are undefined. It isn't clear whether "N of M" and "jump" follow the shuffled order or page order. Opening a search result may or may not reset Shuffled to Page order. Previous on 1 and Next on M could wrap or disable. A pile of 1, and editing or deleting a note while the pile is open, have no rules. An all-Books search result opens "its Book's pile", but the Esc return target isn't stated (EXPERIENCE.md § Component Patterns → Pile). *Fix:* Index follows the current order. Opening a result opens in Page order. Previous and Next are disabled at the ends (no wrap). Edit and delete are allowed in the pile, and after a delete it moves to the next note. Esc returns to the list scroll position, with the last viewed note focused.
- **[low]** "See card notes · 0" when a Book has no notes, and the button's accessible name with the count, aren't specified (EXPERIENCE.md § Component Patterns → Main book card). *Fix:* Show "See card notes" without a count at 0, and name it "See card notes, 7 notes".

## Stats

- **[medium]** Custom range end before start, future ranges, partial months (15 Mar–10 Apr), and "All time" over many years (120+ monthly bars) are undefined. The start of "All time" isn't stated (first finish or first Book added). Whether a finish counts by local date or UTC timestamp isn't stated either (EXPERIENCE.md § Component Patterns → Stats range picker, Monthly bars). *Fix:* Swap reversed custom dates, or disable the end date before the start. Bar partial months by the dates in range. For ranges over 24 months, show one bar per year. All time starts at the first finished Reading. Store the finish as a local date.

## Duplicate warning and agent contract

- **[high]** Duplicate matching and the agent's confirmation step are fragile. Author comparison rules aren't stated (FR-3 normalizes titles only). Semicolon splitting, case, and "Le Guin, Ursula" vs "Ursula Le Guin" are unspecified. ISBN-10 vs ISBN-13 of the same edition don't match. The dialog names "the existing Book" (singular) when there may be several matches. It isn't stated whether Save changes in edit mode runs the check. After the skill chooses **Add anyway**, or adds "Dune" when "Dune Messiah" exists, its documented check "1 book matches" fails, because search is substring-based (EXPERIENCE.md § Component Patterns → Duplicate dialog; Agent Label Contract outcome signals; PRD FR-3). *Fix:* Normalize authors as titles are normalized (case, whitespace, per semicolon item). Optionally convert ISBN-10 to ISBN-13 before comparing. Name up to 3 matches plus "and N more". Run the check on edit only when title, author, or ISBN changed. Change the agent's success signal to the `status` text "Added *Title*." plus "a row whose title equals *Title*" rather than a count of 1.
- **[medium]** Field validation beyond "required" has no messages: Pages 0 or 1.5, Edition 0, Year 99999, ISBN with letters, and a non-image or 30 MB Cover file. The Type select has no placeholder rule, so "required" can never fail if Paperback is preselected. These are outcomes the unattended skill must read (EXPERIENCE.md § Agent Label Contract; § State Patterns → Validation error). *Fix:* Add a validation table with each rule and its exact message. Give the Type select an empty first option. Downscale covers on upload (for example, a long edge of 1200px) and refuse non-images with a message.
- **[low]** Edit mode reuses the New book panel, but the side panel is "anchored over the Catalog" while Edit opens from Book detail. Post-save behavior (live region text, highlight, where focus goes) is defined only for Add (EXPERIENCE.md § Component Patterns → New book panel; DESIGN.md § Layout → Side panel). *Fix:* The panel opens over the current page. On Save changes: status "Saved *Title*.", stay on Book detail, focus returns to Edit.

## Backup, restore, concurrency

- **[high]** Two tabs, and the agent's browser, have no rules. With local browser storage, two open tabs each hold stale state, and the last write wins (a lost page update or card note). More seriously, the cataloging skill drives a browser through Playwright, which by default uses its own profile. Unless the skill uses the user's profile, it writes to a separate local store, and Flow 1's climax ("Oleg comes back… 19 new spines") never happens (EXPERIENCE.md § Foundation → Local-first, Users; Flow 1). *Fix:* State the expectation for architecture: one shared store, with a cross-tab change listener such as a `storage` event or BroadcastChannel that reloads state, or a "bookvie is open in another tab" notice. Add to Flow 1 that the skill must run in the user's browser profile, or against the same local origin and store. Flag this in prd-deltas.
- **[medium]** Restore failure modes collapse into one message. An older-version export (needs migration), a newer-version export, a truncated or corrupt file, and a valid bookvie file with broken references all have no rule. "Restore done: Home reloads" doesn't say whether the app navigates away from Backup. It isn't stated whether "Last export" after a restore comes from the file or stays local ("No export yet" on the new laptop would be misleading). Theme and Catalog view preferences aren't stated as included or excluded (EXPERIENCE.md § State Patterns → Restore; prd-deltas #19). *Fix:* Accept older versions through migration. Refuse newer versions with "This export is from a newer bookvie." Refuse corrupt files with "This file is damaged. Nothing was changed." Validate everything before replacing anything. After a restore, navigate to Home. Keep "Last export" local. Preferences are not restored.
- **[medium]** Export size and duration aren't specified. 500 covers at phone-photo size could make a single file of hundreds of MB. "No loading state, deliberate" doesn't hold for exporting or restoring that much data. "Last export: today" is set on click even if the download is cancelled or blocked, which shows false safety (EXPERIENCE.md § Component Patterns → Backup page; memlog "no loading state"). *Fix:* Downscale covers on upload. Show a busy state ("Exporting…", button disabled) for operations over about 300ms. Set "Last export" only after the file has been generated and handed to the download. Note that the browser can't confirm the save.
