# Accessibility review — bookvie UX spines (DESIGN.md + EXPERIENCE.md)

Reviewer lens: adversarial accessibility (WCAG 2.2 AA + practical ARIA), with the unattended AI cataloging skill treated as a first-class assistive-tech user. Date: 2026-10-28. Contrast values below were computed from DESIGN.md frontmatter hex values (WCAG relative luminance); the script is `/private/tmp/claude-501/-Users-Oleg-Anastassov-github-bookvie/0726524b-980e-439f-9f02-0ff72d8cfbce/scratchpad/c.py`.

## Verdict

The spines have a stronger accessibility floor than most drafts: they use native elements, an explicit Agent Label Contract, `alertdialog` for duplicates, live-region outcomes, spine names that carry status, and darkened unread outlines. Every text pair DESIGN.md claims passes, and I reproduced those values. Still, the unattended cataloging path has several ways to fail silently. Two examples: the "(required)" label text conflicts with the label contract, and two "Cancel" buttons can be open at once with opposite effects. Outcome text can also be stale, and there is no save-failure signal. Several keyboard and focus models are also left as assumptions or not specified at all: the bookcase grid, where focus goes after a dialog removes its own trigger, and the popover. The 1024px no-reflow floor conflicts with WCAG 1.4.10. Fix the high items before implementation stories are written.

Counts: **0 critical · 6 high · 15 medium · 14 low**

---

## Agent Label Contract and machine-readable outcomes

- **[high]** The "(required)" marker is likely to become part of the accessible name. DESIGN.md puts "(required)" next to the label. If it sits inside `<label>`, the name of Title becomes "Title (required)". That breaks the contract's rule "Visible label and accessible name always stay identical", and an exact `getByLabel('Title')` will miss it. Separately, the default substring match `getByLabel('Title')` also matches **Subtitle**, so the skill can hit an ambiguous or wrong field without anyone watching (DESIGN.md § Components → New book panel; EXPERIENCE.md § Agent Label Contract). *Fix:* Keep "(required)" outside the `<label>`, or wrap it in `aria-hidden="true"` and expose requiredness with `required`/`aria-required="true"`. State in the contract that the accessible name is exactly the bare label. Tell the skill and the tests to match labels exactly, and list Title/Subtitle as a known substring pair.
- **[high]** Two buttons named "Cancel" can be in the DOM at once, with opposite effects. While the Duplicate `alertdialog` is open over the New book panel, the panel's footer **Cancel** (discard everything, close the panel) and the dialog's **Cancel** (go back to the panel with fields intact) share one name. The contract only says to "resolve within the open dialog", which pushes scoping onto the skill. If the skill picks the wrong one, the book is silently discarded (EXPERIENCE.md § Agent Label Contract, § Duplicate dialog; DESIGN.md § Duplicate dialog). *Fix:* Give the duplicate's dismiss button a unique name such as **Don't add** or **Back to form**, and add it to the contract. Also require the panel to be `inert` (native `showModal()` stacking) while the alertdialog is open, so only one set of buttons is exposed.
- **[high]** Outcome text can be stale, and a save failure has no signal. "One polite `status` region per page" keeps "Added *X*." from the previous book. A live region does not re-announce identical text, for example the same validation alert after a retry, or "Added Dune." after Add anyway. No state is defined for a write that fails (storage quota or a database error), and the "no failure states anywhere" rule rules one out. An unattended skill can read the last book's "Added …" and report success (EXPERIENCE.md § Accessibility Floor → Live regions, § State Patterns, Agent Label Contract → Outcome signals). *Fix:* Clear the `status` and `alert` regions when the panel opens and on every **Add book** press. Set the new text after a tick so repeated text is announced again. Add an outcome signal: `alert` "Not saved. bookvie couldn't write to this computer's storage." with the panel kept open. Calm wording, but it must exist.
- **[medium]** The "Search titles" check is ambiguous. "1 book matches" fails for titles that are substrings of others (Dune vs Dune Messiah) and after an **Add anyway** (2 matches). The skill cannot tell its new book apart using the count alone (EXPERIENCE.md § Flow 1 step 5, § Search field). *Fix:* Tell the skill to confirm by the accessible name of a remaining spine button or list row ("*Title* by *Author*, not read yet"). State that filtered-out spines are removed from the accessibility tree (`hidden`/`display:none`), not only made invisible. Debounce the count announcement.
- **[medium]** The contract leaves out controls the skill or tests will meet. Missing entries: the panel's close "×" (name it **Close**, distinct from Cancel), the eight swatch buttons and the "From cover" chip (they need names such as "Sage" and an `aria-pressed` state), the edit-mode dialog name "Edit book" and **Save changes** (still [ASSUMPTION]), the exact Type option values (still [ASSUMPTION]), Pages accepting decimals (an `input type=number` without `step=1` accepts 12.5), and the Card notes search name (EXPERIENCE.md § Agent Label Contract). *Fix:* Add these rows and resolve the [ASSUMPTION]s before tests are written. Name the Card notes search "Search card notes" so "Search titles" only ever means the Catalog.
- **[medium]** "Search titles" is defined only as a placeholder. DESIGN.md gives "Placeholder 'Search titles'" and no visible label. That violates EXPERIENCE.md's "Every control has a visible label". The visible hint disappears as soon as text is typed, and the placeholder is a fallback name source that `getByLabel` does not match (DESIGN.md § Search field; EXPERIENCE.md § Accessibility Floor → Names). *Fix:* Give the search field `aria-label="Search titles"` (or a visible or visually hidden `<label>`), keep the placeholder as decoration only, and list the name source in the contract.
- **[low]** The spine-to-popover relationship isn't exposed. *Fix:* Spine buttons get `aria-haspopup="dialog"` and `aria-expanded`. Name the popover with `aria-labelledby` pointing at its title heading (EXPERIENCE.md § Spine, § Spine popover).

## Keyboard and focus

- **[high]** The bookcase keyboard model for about 500 spines is only an [ASSUMPTION] and is underspecified. Rows reflow with viewport width, so Up/Down has no stable meaning. These are all undefined: the container role (roving `tabindex` over buttons in a generic `div` is not a recognized composite), Home/End and PageUp/PageDown, position info ("12 of 500"), what happens when the focused spine is filtered out or the sort changes, and how focus "moves to the new spine" when that row is lazily unrendered (EXPERIENCE.md § Bookcase → Keyboard, Catalog scale, Highlight after add). *Fix:* Decide the pattern and remove the [ASSUMPTION]. For example: container `role="list"` named "Bookcase, 54 books", spines as list items with buttons; one Tab stop; Left/Right step through spines; Up/Down move to the nearest spine in the visual row above or below; Home/End go to the row's ends and Ctrl+Home/End to the library's ends. If the focused spine disappears, focus moves to its nearest neighbor or to the search field. The target row is rendered before focus moves. Apply the same model to the Home slice.
- **[high]** Focus has no defined destination when a dialog removes its own trigger. After **Done** in the Finish dialog, the page field and **Update** are gone (no Main book). When finishing starts from Book detail, the app navigates to Home. Start reading may navigate to Home (Flow 3), Delete book removes the current page, Restore reloads Home, and a dialog opened from the popover has no popover to return to. "Return focus to the opener" can't work in any of these cases, so focus drops to `<body>` (EXPERIENCE.md § Interaction Primitives → Esc, § Finish dialog, § Start dialog, § Confirm dialog). *Fix:* Add a focus-destination table. Suggested targets: Finish Done → **Start reading** for the suggested Up next, or the "No Main book." heading. Start confirmed → the new Main book's page field or heading. Delete → Catalog search or the neighboring spine. Restore → Home `h1`. Popover-launched dialog closed → the originating spine.
- **[medium]** The spine popover's focus model is undefined. "Non-modal dialog" doesn't say where focus goes on open (the title, the primary action, or ×), whether Tab leaves the popover into the next page element or wraps, or what happens to an open popover when focus leaves it. The 500px popover anchored above a spine can also be clipped at the viewport edges, on the top shelf row, and under zoom (EXPERIENCE.md § Spine popover; DESIGN.md § Spine popover). *Fix:* On open, focus the first actionable control and give the dialog `aria-labelledby` pointing at the title. Tab past the last control closes the popover and continues after the spine. Close on focus-out. Add collision-aware placement (flip below, shift inward) with `max-width: calc(100vw - 32px)`.
- **[medium]** The "/" shortcut fails WCAG 2.1.4 (Character Key Shortcuts) as written. It is a single printable-character shortcut with no way to turn it off or remap it, so speech-input users who dictate "slash" are affected. "Ignored while typing in a field" also doesn't cover `select`, `contenteditable`, IME composition, modifier keys, or an open modal or popover, where it would move focus out of a trapped dialog (EXPERIENCE.md § Interaction Primitives). *Fix:* Add a "Keyboard shortcut: / focuses search" on/off setting (default on), or require a modifier. Ignore the key while any modal or popover is open, inside editable or select elements, during composition, and with any modifier pressed.
- **[medium]** There is no skip link and no landmark, heading, or page-title spec (WCAG 2.4.1, 2.4.2, 1.3.1). Every page puts 8 tab stops first (5 nav items plus 3 theme options). Single-page-app route changes don't announce the new page or move focus (EXPERIENCE.md § Accessibility Floor). *Fix:* Add a "Skip to content" link, `header`/`nav`/`main` landmarks, one `h1` per page ("Home", "Catalog", and so on), a `document.title` per route, and move focus to the `h1` (or announce it) on route change.
- **[low]** A disabled control removes its explanation. The 4th "Mark as Side read" is disabled with the hint "Up to 3 side reads.", but a natively disabled button is skipped by Tab, so keyboard and screen-reader users never meet the hint. Pile **Previous**/**Next** disabling at either end also drops focus (EXPERIENCE.md § Book detail, § Pile). *Fix:* Use `aria-disabled="true"` with `aria-describedby` pointing at the hint. Keep Pile buttons focusable at the ends, or wrap around.
- **[low]** The sticky panel footer can cover focused fields (WCAG 2.4.11 Focus Not Obscured). *Fix:* Add `scroll-padding-bottom` equal to the footer height in the New book panel (DESIGN.md § New book panel).

## Screen reader semantics and live regions

- **[medium]** Page-field and card-note errors are silent. State Patterns says "Inline message, nothing saved, value kept", with no `aria-invalid`, no `aria-describedby`, and no announcement. That contradicts the Accessibility Floor ("One `alert` region for … validation failure"). "of M" is also not tied to the field (EXPERIENCE.md § State Patterns → Validation error (Page field, Card note panel), § Page field). *Fix:* Apply the New book rules here: `aria-invalid`, a message linked with `aria-describedby`, and the message announced through the `alert` region. Link "of 330" to the field with `aria-describedby`.
- **[medium]** Pile navigation isn't announced. **Next** changes the note while focus stays on the button, so a screen reader hears nothing. The order toggle and "N of M" have no semantics (EXPERIENCE.md § Pile). *Fix:* Put the card in an `aria-live="polite"` region (or announce "Note 3 of 7, p.42: …"). Make Page order · Shuffled two `aria-pressed` buttons, or a radio group named "Order".
- **[medium]** The rating and "Purpose fulfilled?" controls have no defined semantics, and the selected star is shown by color only. "Five outline stars (sage when selected)" makes the selection a color-only state change (1.4.1). Skippable answers have no way to clear a choice (DESIGN.md § Finish dialog; EXPERIENCE.md § Finish dialog). *Fix:* Make both radio groups ("Rating", "Purpose fulfilled?") with named options ("4 stars"). Show selected stars filled, not only recolored, and add a "No rating" option or a way to clear.
- **[low]** The finish announcement races focus changes. The dialog closing, focus moving, the card re-rendering, and the "Finished *X*. 25 of 54 finished." message all happen at once, and screen readers often drop polite messages during a focus change (EXPERIENCE.md § State Patterns → Finish moment). *Fix:* Announce after focus has settled on the new target (see the focus-destination fix), or make the new focus target's name include "Finished *X*".
- **[low]** Some dynamic results are not announced: the Pace calculator result changing as you type, numbers after a Stats range change, and the Card notes search count. Only the Catalog search count is announced (EXPERIENCE.md § Pace calculator, § Stats range picker, § Card notes list). *Fix:* Use `<output>` or a polite region for the pace result and a debounced "N notes match". Stats can announce "2 books, 610 pages this month".
- **[low]** Toggle groups have no names. The theme and Catalog-view toggles are groups of `aria-pressed` buttons with no group label (EXPERIENCE.md § Theme toggle, § Catalog view toggle). *Fix:* Use `role="group"` with `aria-label="Theme"` / `"Catalog view"`. The glyphs are `aria-hidden` and the text labels stay visible.
- **[low]** Spine color, a personal association by design, is never exposed, and the popover gives no current-color state (EXPERIENCE.md § Spine popover → Change color). *Fix:* Show the current color in the popover ("Color: teal, from cover"), name the swatches, and announce "Color set to Teal."
- **[low]** Mini bars and the gauge need complete progressbar attributes. Each "Waiting for you" mini bar is a progressbar but has no name. The gauge omits `aria-valuemin="0"` (EXPERIENCE.md § Gauge, § Accessibility Floor → Progress). *Fix:* Use `aria-labelledby` pointing at the row title, `aria-valuetext="page 120 of 330, 36%"`, and an explicit `aria-valuemin`.

## Color and contrast (computed)

All text pairs in DESIGN.md § Contrast reproduce correctly. Pairs used on screen but missing from the table also pass: `ink-tertiary` on `shelf-wall` 4.66 / 6.02, and the `accent` link on `shelf-wall` 4.55 / 7.27. The failures are non-text:

- **[medium]** The difference between read and unread spines has no contrast floor. Curated **sage** (2.92) and **ochre** (2.63) fall below 3:1 against the light `shelf-wall`. Dark **plum** is 2.78 against a neighboring unread fill. User-set and cover-derived colors are only nudged for *label* contrast, so a pale cover color in light theme, or a near-black one in dark theme, makes a read spine blend into the wall or look like an outlined unread spine (DESIGN.md § Spine colors, label rule). *Fix:* Add a second constraint to the nudge: at least 3:1 against `shelf-wall` in both themes. Because spine colors are the same in both themes, that means relative luminance between ≈0.142 and ≈0.242, a band where a white or ink label still reaches 4.5:1 near its ends. Alternatively, give every read spine a 1px darker or lighter edge.
- **[medium]** Spine markers fail 1.4.11 in two places. `marker-waiting` sand is 2.75:1 on the light `spine-unread-fill`. On colored spines, which a re-read or a paused finished book will have, sky and sand drop to 1.1–2.3:1 against every curated color in both themes (DESIGN.md § Colors, § Spine → Markers). *Fix:* Darken light-theme sand to about `#8C7B5C` (4.01 on fill, 3.43 on wall), and give each marker a 1.5px ring in `spine-unread-fill` or `page` so the dot keeps 3:1 on any spine color.
- **[medium]** Form-field boundaries are invisible. The `line` border is 1.33:1 on `surface` and 1.26:1 on `surface-inset` (dark: 1.30 / 1.38). It is the only edge that marks the page field, search, all New book fields, the pace field, and the hex field, which fails 1.4.11 (DESIGN.md § Page field, § New book panel, § Search field). *Fix:* Add an `input-border` token at ≥ 3:1, for example `#8A8273` light (3.80 on surface) and `#767A6F` dark (3.53). Keep `line` for decorative hairlines only.
- **[medium]** The selected state of segmented controls is barely visible. Theme, Catalog view, Purpose fulfilled, Stats presets, and Pile order all show selection with an `accent-soft` fill (1.22:1 vs `surface`, 1.29 dark) plus weight 600 (DESIGN.md § Theme toggle, § Catalog view toggle). *Fix:* Add a non-color indicator with ≥ 3:1 contrast: a 2px `accent` underline or border on the selected option, or a check glyph.
- **[medium]** Light-theme mini bars fail. `accent-mid` on `accent-soft` is 2.11:1 (dark passes at 3.23). The proportion isn't shown elsewhere, because the row only shows "p.N" (DESIGN.md § Section pane). *Fix:* Use `accent` for the fill (4.48 on `accent-soft`), or add the percentage or "of M" as text.
- **[medium]** The spine focus ring has weak contrast against its surroundings. A 2px ring at 2px offset fills the entire 4px spine gap, so its outer edge touches neighboring spines (accent vs curated colors: 1.01–1.73 light, 1.40–2.38 dark). In dark theme, its bottom edge lies over the walnut plank (`accent-dark` vs `birch-plank-dark` 2.70). The inner edge against the wall passes (4.55 / 7.27), so this is borderline, but it affects the app's main interaction (DESIGN.md § Focus ring, § Layout → spine-gap). *Fix:* Use a two-tone ring for spines, like the highlight ring (`0 0 0 2px page, 0 0 0 4px accent`), or widen the gap to 6px. Check the plank edge in dark theme.
- **[low]** The search-match highlight relies on a background that is barely visible: `accent-soft` vs `surface` is 1.22:1 (DESIGN.md § Card notes list). *Fix:* Use `<mark>` with an underline or weight change in addition to the tint.
- **[low]** The library meter track can't be seen. `line` vs `shelf-wall` is 1.11:1, so the bar's full length, and therefore the proportion, is invisible. The text "X of Y finished" makes up for it (DESIGN.md § Library meter). *Fix:* Use a darker track, or accept it as decorative and document that.
- **[low]** The contrast table is missing pairs that are in use: the placeholder text color, the star outline, the "×" close glyph against `surface`, and dark `ink-tertiary` on `accent-soft` (4.39, which fails if any hint ever sits in a selected option) (DESIGN.md § Contrast). *Fix:* Add these rows and set the placeholder and star outline to ≥ 4.5 and ≥ 3:1 respectively.
- **[low]** Forced-colors / Windows High Contrast isn't addressed. Read spine fills, Main book partial fills, gauge fills, and markers are backgrounds that forced-colors mode removes, so read and unread look the same. *Fix:* Add `@media (forced-colors: active)` rules: read spines get `CanvasText`/`Highlight` fills via `forced-color-adjust: none` on the fill element, and gauges get a border.

## Motion

- **[low]** Reduced-motion coverage is incomplete. "Only two motions exist" ignores motion the spines imply elsewhere: the side panel and popover appearing, the smooth scroll to the new spine after an add, the gauge moving 57→64%, the shelf reflowing during search, and theme-switch transitions (EXPERIENCE.md § Interaction Primitives → Motion, § Bookcase → Highlight after add). *Fix:* State a global rule. Under `prefers-reduced-motion: reduce`, all transitions and animations are none and `scrollIntoView` uses `behavior: 'auto'`. Panels and popovers appear without sliding.

## Zoom, reflow, and text

- **[high]** The 1024px no-reflow floor fails WCAG 1.4.10 (Reflow) at 200–400% zoom. At 200% on a 1440px laptop, the CSS viewport is 720px. Every page, including text-only ones (Card notes, Backup, Stats, the New book form), then scrolls in two directions. The fixed 440px panel and 500px popover make it worse. The bookcase itself already reflows by row count, so the floor only hurts (EXPERIENCE.md § Foundation, § State Patterns → Narrow window; DESIGN.md § Layout). *Fix:* Keep 1024px as the design target, not a hard floor. Below it, stack Home's two columns, let the panel go full width, cap the popover at `100vw - 32px`, and let the toolbar wrap. No phone *design* is needed, only a layout that doesn't break.
- **[low]** Vertical spine labels don't hold up under text spacing. Spine heights are computed in px from 11px / 10.5px vertical text. User text-spacing overrides (1.4.12) or a minimum font-size setting will clip or overflow labels, and 10.5px vertical text is hard to read at any zoom. The full title in the name and the popover mitigates this (DESIGN.md § Layout → Spine sizing, § Typography). *Fix:* Measure the rendered label to set height, and clip with an ellipsis instead of overflowing. Consider 12px minimum for spine labels. Make sure the popover is the documented way to read a title.
