### Process (session logs and commits)

- **E10-R1: the ATDD step wrote border assertions that Chromium can't produce, and the build had to rewrite them. Medium (process).**
  - **What happened:** the ATDD checklist's AC-2 and AC-9 rows assert the select's right border and the toggle's borders as `1.5px` (`atdd-checklist-10-1-*.md:64,71`). Chromium 156 floors a computed border width to whole CSS pixels at every device scale factor, so `toHaveCSS('border-…-width', '1.5px')` can never pass.
  - The build rewrote those assertions to compare the border with the same token, which made them a tautology. The build's own review caught that and asserted the literal `'1px'` (spec Review Triage Log, rows 2, 5, 12, 14). The code review then found that `'1px'` can't tell 1.5px from 1px and pinned `--text-field-border: 1.5px` beside it (`e6dcc1e`; a mutation to 1px now fails AC-2).
  - **Known before:** the same floor was recorded in the Epic 1 retro ("The 1.5px outline renders as 1px", `epic-1-retro-2026-11-03.md:194`), and Epic 8 worked around it for the unread typeset border (`epic-8-retro-2026-11-13.md:98`).
  - **Why item 66 didn't catch it:** the ATDD probe rule (`_bmad/custom/bmad-testarch-atdd.toml:7`) covers measuring *helpers*. A built-in `toHaveCSS` read of a fractional width isn't a helper, so it was never probed.
  - **This instance:** accept. `e6dcc1e` pins the token and the floored value, and the mutation check proves it.
  - **Prevention:** action 71.
