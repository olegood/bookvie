## Intent

**Problem:** The `card-notes` view's groups and scope carry only `bookId` and `title`, so Epic 14's boxes (14.2) and the open box strip (14.3) can't be drawn in the Book's spine color without a second request.

**Approach:** Add `spineColor` (the Book's stored, resolved `spine_color`, AD-11, exactly as stored) to `CardNotesGroup` and `CardNotesScope`, regenerate the client types with `api:gen`, and change nothing else (AR62, AR63).

## Boundaries & Constraints

**Always:**
- The value is `book.spine_color` as stored: the same value the `book` and `catalog` views give. Never re-resolve it from `spine_color_user` / `from_cover` / `curated`.
- The scope carries it even for a Book with no notes.
- `schema.d.ts` changes only through `npm --prefix frontend run api:gen`; it is never hand-edited or formatted. No other file is reformatted.
- `get_card_notes` keeps returning the view as is, and its registered description stays unchanged.

**Never:**
- No domain, store, backup-format, intent, agent-tool or page change. Nothing visible changes.
- No edit to the existing Card notes e2e specs.
- No banned git command (AGENTS.md "Story pipeline", Epic 8 retro item 64).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Unscoped | Books with notes (user, cover, palette, odd stored color), one without notes | each group has `spineColor` = stored value; order, notes, `scope: null` unchanged; no group for the Book without notes | No error expected |
| Scoped with notes | `?book=<id>` | `scope = {bookId, title, spineColor}`; the one group has the same color | No error expected |
| Scoped without notes | `?book=<id>` of a Book with no notes | `scope.spineColor` is its color; `groups: []` | No error expected |
| Unknown Book | `?book=<unknown>` | 404 `book_not_found` | unchanged refusal |
| Color changed | popover `set-spine-color` or `edit-book` | next read carries the new color in group and scope | No error expected |

</intent-contract>
