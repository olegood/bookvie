### Diff review: bugs

- **E11-B1. `--dev` doesn't refuse a case variant of the real library when that folder doesn't exist yet.** *fix (item 76)*
  - Source: `backend/bookvie/cli.py` `_refuses_real_library` uses `instance.same_folder` (`backend/bookvie/instance.py:166`). `os.path.samefile` raises for a missing folder, and the fallback `Path.resolve()` comparison is case-sensitive.
  - Reproduced in this retro: with `HOME` set to a scratch folder that has no `bookvie-data`, `bookvie --no-browser --dev --data-dir ~/BOOKVIE-DATA` started serving and created `BOOKVIE-DATA`. On a case-insensitive disk that is the real library's folder, and production would later open a library the dev server filled.
  - The function's docstring claims "a case variant … a folder that doesn't exist yet". The `case` leaf in `test_dev_mode.py` always creates the folder first, so the combination was never tested.
  - Impact today is low, because Oleg's real `~/bookvie-data` exists. It is the P0 risk the epic exists for, though.
  - Found by: edge-case lens.
- **E11-B2. A production server serves the amber icon at `/favicon-dev.svg`.** *fix (item 76)*
  - Source: the SPA catch-all in `backend/bookvie/http/app.py` serves any top-level static file, and 11.2 put `favicon-dev.svg` into `static/`.
  - Reproduced: `GET /favicon-dev.svg` on a production app returns 200 `image/svg+xml` with `#8C5E0E`. Nothing links it, but it breaks "no amber anywhere in production" (`epic-11-context.md`).
  - The comment above the favicon route also says the catch-all would serve the file "uncached". In fact it serves it without `Cache-Control`.
  - Found by: adversarial and edge-case lenses.
- **E11-B3. `index.html` is served without `Cache-Control`, and Story 11.4's notice relies on a fresh one.** *fix (item 76)*
  - Source: the catch-all responds with `last-modified` and `etag` and no `cache-control` (checked with a TestClient in this retro), so Chrome may cache it heuristically.
  - The notice's Reload revalidates the document, so the notice itself works (behavior check below). A tab newly opened after an update, though, can still get an old `index.html` whose hashed assets `emptyOutDir` deleted.
  - This predates Epic 11. The epic is the first feature that depends on getting the new bundle. The favicon already gets `no-cache`.
  - Found by: adversarial lens.
