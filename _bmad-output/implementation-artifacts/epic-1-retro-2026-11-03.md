### Cross-story boundaries (diff review)

**F-R1. A stale Edit panel silently undoes a color change made elsewhere** (medium for multi-tab use, low for one tab; stories 1.11/1.14, also 1.13)

- **Source:**
  - `frontend/src/pages/NewBookPanel.tsx:96` copies `spineColorUser` once, when the panel opens.
  - `backend/bookvie/intents/edit_book.py:220-227` re-resolves the color whenever `fields.spine_color != book.spine_color_user`.
- **What goes wrong:** Tab A opens Edit. Tab B changes the color in the popover. Tab A saves, and the old color comes back with no warning.
- **Why it can happen:** no intent carries a version or precondition, so every field is last-writer-wins.
- **Variant:** a stale "Remove cover" removes a cover uploaded later in another tab.
- **Same tab:** prevented, because the Edit panel is modal.
- **Instance:** accept. Oleg uses one tab (decided 2026-11-03), so last-writer-wins is recorded as an accepted deviation (action 7).
- **Prevention:** AD-3 says nothing about concurrent intents from several tabs. Decide the policy once, in the architecture spine.

**F-R2. A malformed multipart body returns FastAPI's `{detail}` 400, not the error envelope** (low; story 1.5 against 1.7 and 1.11-1.14)

- **Source:**
  - `backend/bookvie/http/api.py:343-349`.
  - No `HTTPException` handler on `/api`.
- **Examples:** an `intent` part over 1 MB, or broken multipart framing.
- **Client impact:** none; it is mapped to `couldnt_save`.
- **Contract impact:** it breaks the 1.5 rule that `{detail}` never reaches the browser.
- **Instance:** defer (small fix).
- **Prevention:** add a contract test that sends a malformed body to each intent route.

**F-R3. A cover being served can race a delete or replace and return a 500 instead of a 404** (low, plausible; not run; stories 1.12/1.13)

**F-R4. After a delete, the next new book can repeat a neighbour's curated color** (low, cosmetic; stories 1.12/1.8)

### Checked and clean

- **Layering:** no import violations and no cycles. `tests/test_layers.py` covers every package and tests itself.
- **One commit path:** every intent commits through `intents/commit.py:34` → `store.apply`, and no intent writes files itself (AD-3, AD-12).
- **Delete against cover files:** the old cover is removed after the swap, failed commits remove the files they wrote, and startup sweeps orphans (`store.py:322-339`).
- **Store lock against cover writes:** Pillow decodes outside the lock; the file write, commit and old-file delete all happen under it.
- **Edit against duplicate detection:** edit checks for duplicates inside the commit (`edit_book.py:202`), and the panel offers "Save anyway".
- **Host/Origin guard:** global, outermost, and refuses `Origin: null`.
- **Error envelope:** refusals, 422, 500, 503, 413 and the book view's 404 are all enveloped. The only exception is F-R2.
- **Cache invalidation:** every intent goes through `sendIntent`, which invalidates all views, and there are no optimistic patches. Cover tint and spine color come from the server everywhere.
- **New and Edit book:** one shared form driven by a `MODES` table, not a copy.
- **Duplicate and Confirm dialogs:** they share `useAlertDialog`, with one focus-trap helper.
- **CSS:** no hex colors outside `tokens.css`.
- **TR8 matrix:** add, duplicate, edit, delete and set-spine-color each have a fault → 503 test with byte-identical `library.json`, an invariants-after-success check, a 409 `book_not_found` test where it applies, and a test for every new error code. The gaps are only F-S4.
